# 設置手順(所要時間:約15分)

お客様がフォームを送信すると、

- **Googleスプレッドシート** に1件ずつ記録され、
- **あなたのGmail** に通知メールが届く

ようにするための手順です。
プログラミングの知識は不要です。

---

## 全体の流れ

```
お客様のスマホ・PC
   │  フォームに入力して「送信」
   ▼
フォーム画面(GitHub Pages で公開)
   │
   ▼
受信プログラム(Google Apps Script)
   ├─▶ スプレッドシートに記録
   └─▶ あなたのGmailに通知メール
```

---

## ステップ1:受信用スプレッドシートを作る

1. Googleアカウントにログインし、
   [Googleスプレッドシート](https://sheets.google.com) を開きます。
2. 「空白」で新しいシートを作り、
   名前を「ヒアリングシート回答」などにします。

## ステップ2:受信プログラムを貼り付ける

1. スプレッドシートのメニューから
   **拡張機能 → Apps Script** を開きます。
2. 最初から書かれているコードをすべて消し、
   このリポジトリの `gas/Code.gs` の中身を
   丸ごと貼り付けて保存(💾)します。
3. **通知先のメールアドレスを登録します。**
   アドレスがGitHubで公開されないように、コードには書かず、
   Googleの中だけに保存する方法を使います。
   1. Apps Script 左側の **歯車マーク(プロジェクトの設定)** を押します。
   2. 一番下の **「スクリプト プロパティを追加」** を押します。
   3. プロパティに `NOTIFY_TO`、値に通知を受け取るメールアドレスを入れて、
      **「スクリプト プロパティを保存」** を押します。
      複数人に送るときは、カンマ区切りで入れます。
   4. 同じ画面の **タイムゾーン** が「(GMT+09:00) 東京」になっているかも確認します。
4. 必要なら、ファイル先頭の設定を変更します。
   - `SEND_CUSTOMER_COPY`:`true`(初期設定)だと、
     お客様に受付番号入りの「受付完了メール」が届きます。
     同じアドレスへは1時間に3通までに制限しています(いたずら対策)。
   - `SHOP_NAME` / `SHOP_TEL` / `SHOP_HOURS`:メールに載せる店舗名・電話番号・受付時間。
   - `REPLY_TIME`:「○○以内にご連絡します」の目安(例:`2営業日以内`)。

## ステップ3:動作テストと初期設定

1. 画面上部の関数選択で **testSubmit** を選び、
   **実行** を押します。
2. 初回は「承認が必要です」と出るので、
   自分のアカウントを選んで許可します。
   (「Googleで確認されていません」と出た場合は、
   「詳細」→「〜(安全ではないページ)に移動」で進めます。
   自分で作ったプログラムなので問題ありません。)
3. スプレッドシートに「パソコン」シートができ、
   通知メール(提案のヒント付き)が届けば成功です。
   確認後、テストの行は削除して構いません。
4. スプレッドシートの画面に戻り、再読み込みします。
   上部のメニューに **「ヒアリングシート」** が増えています。
5. **「ヒアリングシート」→「初期設定(自動お知らせ・プルダウン)」** を1回だけ実行します。
   - 毎朝9時ごろ:24時間以上「未対応」の回答を、メールでお知らせ
   - 毎朝7時ごろ:「集計」シートを更新
   - 「対応状況」をプルダウンで選べるようにし、「未対応」を赤、「成約」を緑で色分け

> 💡 写真の保存(Googleドライブ)や自動実行のため、
> 「Googleドライブのファイルの参照・作成」などの許可を求められます。
> お客様の写真は、ドライブの「ヒアリングシート写真」フォルダに保存されます。
> このフォルダは、しょーまさんだけが見られる設定です。

## ステップ4:ウェブアプリとして公開する

1. 右上の **デプロイ → 新しいデプロイ** を押します。
2. 種類の選択(⚙)で **ウェブアプリ** を選びます。
3. 次のように設定します。
   - 次のユーザーとして実行:**自分**
   - アクセスできるユーザー:**全員**
4. **デプロイ** を押し、表示された
   **ウェブアプリのURL**(`https://script.google.com/macros/s/…/exec`)
   をコピーします。

> ⚠ コードを修正したときは、
> 「デプロイ → デプロイを管理 → 編集(鉛筆)→ バージョン:**新バージョン** → デプロイ」
> で更新してください。これをしないと反映されません。
> 「新しいデプロイ」を作るとURLが変わってしまうので、注意してください。

## ステップ5:フォームに送信先URLを設定する

1. このリポジトリの `config.js` を開き、
   `GAS_URL: ""` の `""` の中に
   ステップ4のURLを貼り付けて保存・コミットします。
2. 次の項目も、必要に応じて設定します。
   - `SHOP_NAME`:画面に表示する店舗名
   - `REPLY_TIME`:完了画面の「○○以内にご連絡します」
     (`Code.gs` の `REPLY_TIME` と同じにしてください)
   - `SHOP_TEL` / `SHOP_HOURS`:完了画面の「お急ぎの場合は」欄に表示する電話番号・受付時間
   - `CUSTOMER_MAIL`:`Code.gs` の `SEND_CUSTOMER_COPY` と同じにしてください
   - `TURNSTILE_SITE_KEY`:いたずら送信対策を強化するときだけ設定します(下の「任意」の章を参照)

## ステップ6:フォームを公開する(GitHub Pages)

1. GitHubのリポジトリ画面で
   **Settings → Pages** を開きます。
2. 「Build and deployment」の Source を
   **Deploy from a branch** にし、
   公開したいブランチ(通常は `main`)と `/ (root)` を選んで保存します。
3. 数分後、`https://<ユーザー名>.github.io/kaden.hanbai/`
   でフォームが開けるようになります。

> 💡 GitHub Pages は、無料プランでは
> **公開(Public)リポジトリでのみ** 使えます。
> 非公開のままにしたい場合は、
> Netlify や Cloudflare Pages などに
> フォルダごとアップロードしても動きます。

## 質問項目を変えたいとき

`questions.js` だけを編集すれば、
フォーム・スプレッドシート・通知メールすべてに反映されます。
(スプレッドシートの見出し行は、次の回答が届いたときに自動で更新されます。)

## 「一緒に購入したいもの」の商品や質問を変えたいとき

`accessories.js` を編集します。
商品名を足すと選択肢が増え、その商品の質問を書くと、
お客様がチェックしたときだけ質問が表示されます。
スプレッドシートには「マウス:接続方法」のような列が自動で追加されます。

## 「現在お使いの機種」の選択肢を変えたいとき

`models.js` を編集します。
メーカーを選んだときに出る「機種」「容量」などの質問が書かれています。
新しい機種が発売されたら、リストの先頭に追加してください。

## うまく届かないとき

| 症状 | 確認すること |
| --- | --- |
| 「送信先が設定されていません」と出る | `config.js` の `GAS_URL` が空になっていないか |
| 送信完了と出るのに届かない | ステップ4で「アクセスできるユーザー:全員」になっているか。コード修正後に新バージョンでデプロイしたか |
| メールだけ届かない | 迷惑メールフォルダ。Apps Script の「実行数」画面でエラーが出ていないか |

> 補足:Gmail(無料アカウント)からの自動送信は
> 1日あたり上限(目安100通)があります。
> 通常の店舗運用で問題になることはほぼありません。

## 修正が画面に反映されないとき

ブラウザが古いファイルを覚えている(キャッシュ)ことが原因です。
ファイルを変更したら、`index.html` の `?v=20261109a` の部分を
新しい値(例:日付)に書き換えてください。
お客様のブラウザでも、確実に新しい内容が読み込まれます。

## スプレッドシートの使い方

### 対応状況
回答が届くと「対応状況」が「未対応」で記録されます。
プルダウンから「連絡済み」「提案済み」「成約」「失注」「対応不要」を選んでください。
「成約」「失注」を記録しておくと、「集計」シートに成約率が出ます。

### 提案のヒント
回答の組み合わせから、確認したほうがよい点を自動で書き出します
(例:「Macをご希望で、テンキーが必要」「ご予算に対して用途の負荷が高い」)。
あくまで参考情報です。最終的な判断は、お客様と話して行ってください。

### 見積もりのたたき台
1. 「パソコン」または「スマートフォン」のシートで、お客様の行のどこかを選びます。
2. **「ヒアリングシート」→「選択した行の見積もりたたき台を作る」** を押します。
3. 「見積_受付番号」というシートができます。
   本体・Office・一緒に購入したいもの・データ移行・サポートが並びます。
4. 単価は **「価格表」** シートから自動で入ります。
   初めて出てきた品目は、価格表に自動で追加されるので、金額を入れてください。

### 集計
「集計」シートに、回答数・成約率・よくある用途・予算の分布などが出ます。
毎朝自動で更新され、メニューの「集計を更新する」でいつでも更新できます。

## (任意)いたずら送信対策を強化する

標準でも、次の対策が入っています。
- 人には見えない入力欄(機械だけが入力してしまう欄)
- 送信までの時間が5秒未満のものは受け付けない
- 1時間に30件を超える送信は受け付けない
- 同じ受付番号の二重登録を防ぐ

それでもいたずらが続くときは、Cloudflare Turnstile(ロボットかどうかを確認する仕組み)を追加できます。

1. Cloudflare のアカウントを作り、Turnstile でサイトを登録します。
   ドメインには `<ユーザー名>.github.io` を入れます。
2. 発行された **サイトキー** を `config.js` の `TURNSTILE_SITE_KEY` に入れます。
3. 発行された **シークレットキー** を、Apps Script の
   スクリプト プロパティに `TURNSTILE_SECRET` という名前で保存します。
   (シークレットキーは、GitHub には絶対に書かないでください。)
4. Apps Script を「新バージョン」でデプロイし直します。

## 送信が届いたかどうかの確認のしくみ

フォームは送信のあと、受信プログラムに「この受付番号は届いていますか?」と問い合わせます。
届いたことを確認できてから、完了画面を表示します。
確認できなかったときは「もう一度送信する」ボタンが出ます。
同じ受付番号は二重に記録されないので、お客様が何度押しても大丈夫です。

> ⚠ この確認は、**新しい `Code.gs` をデプロイしたあと**に有効になります。
> 古い受信プログラムのままのときは、確認をせずに完了画面を表示します(以前と同じ動き)。
